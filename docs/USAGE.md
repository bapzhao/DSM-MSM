# DSM and MSM calculation source

This package contains calculation code for phase-shift control of aliasing
dissipation in the one-dimensional Burgers equation (DSM) and the two-dimensional
incompressible Navier--Stokes equations (MSM).

It contains no simulation results, saved restart states, figures, plotting
programs or manuscript files. Input states and the filtered-DNS target history
are generated by the supplied calculation code.

The package is a local preparation for the CPC manuscript revision. No public
repository URL, archive DOI or software license has been assigned. See NOTICE.md
before distributing it publicly.

## Contents

| File | Purpose |
| --- | --- |
| `burgers1d/solver.py` | Original convection/viscosity and Smagorinsky update functions |
| `burgers1d/control.py` | Original DSM power evaluation and phase selection functions |
| `burgers1d/run_burgers.py` | Portable entry for the one-dimensional cases |
| `burgers1d/benchmark.py` | Original four-method timing calculation, without plotting |
| `ns2d/run_ns.py` | Dedalus MSM calculation and the reference/raw options |
| `check_source.py` | Small source and numerical-identity checks; no output files |
| `PROVENANCE.json` | Original source paths and SHA256 hashes |
| `IMPLEMENTATION.md` | Conventions, packaging changes and implementation boundaries |

## Installation

The environment names below follow the names used for the one-dimensional and
Dedalus calculations. Existing environments can be used if the dependencies are
already installed.

For the one-dimensional code:

```bash
conda env create -f environment-1d.yml
conda activate 1dburgers
```

Alternatively, in an existing Python environment:

```bash
python -m pip install -r requirements-1d.txt
```

For the two-dimensional code:

```bash
conda env create -f environment-2d.yml
conda activate nsdedalus
```

Dedalus requires a working MPI and FFTW installation. The conda-forge environment
provides these dependencies. Use the Python and MPI launcher from the same
environment. Official installation documentation:
https://dedalus-project.readthedocs.io/en/latest/pages/installation.html

Use one numerical-library thread per MPI process:

```bash
export OMP_NUM_THREADS=1
export OPENBLAS_NUM_THREADS=1
export MKL_NUM_THREADS=1
```

## Check the code without producing simulation results

From the package root:

```bash
python check_source.py
python burgers1d/run_burgers.py --case dns-reference --dry-run
python ns2d/run_ns.py --method msm --dry-run
```

With Dedalus installed, initialize a small field and check reconstruction at
independent shifts, without advancing time or writing snapshots:

```bash
python ns2d/run_ns.py --method msm --kmax 16 --check-only
```

The optional MPI version is:

```bash
mpiexec -n 2 python ns2d/run_ns.py --method msm --kmax 16 --check-only
```

These checks are not a repetition of the manuscript's full numerical study.

## One-dimensional calculations: execute in this order

All paths below are relative to the package root. Output directories must not
already exist. The programs create results only when the following commands
are executed; no such results are included in this package.

### 1. Generate the DNS reference, restart and target history

```bash
python burgers1d/run_burgers.py --case dns-reference --output outputs/1d/reference
```

Defaults: cutoff 512, padded physical grid 1536, viscosity 0.005, time step
0.0002, initial phase seed 2, and final time 0.8002. The additional step after
0.8 allows the forward energy difference at t=0.8 to be evaluated. The LES
filter cutoff is 32.

This command writes `state_t0.300000.npz` and computes `sgs_target.csv` from
the filtered kinetic-energy balance. These are generated inputs for the
continuations, not files that must be obtained from the authors.

### 2. Run the two DSM Smagorinsky-target cases

```bash
python burgers1d/run_burgers.py --case dsm-smag --cs 0.20 --restart outputs/1d/reference/state_t0.300000.npz --output outputs/1d/dsm_cs020
python burgers1d/run_burgers.py --case dsm-smag --cs 0.27 --restart outputs/1d/reference/state_t0.300000.npz --output outputs/1d/dsm_cs027
```

Defaults: cutoff 32, physical grid 64, viscosity 0.005, time step 0.0002,
and time interval 0.3 to 0.8. The coefficient 0.27 is the manuscript's selected
case; this program does not fit or optimize it.

### 3. Run the filtered-DNS-target DSM case

```bash
python burgers1d/run_burgers.py --case dsm-filtered --restart outputs/1d/reference/state_t0.300000.npz --target outputs/1d/reference/sgs_target.csv --output outputs/1d/dsm_filtered
```

The target is the SGS contribution only, with the reference molecular-viscosity
dissipation subtracted. No extra total-energy correction is applied.

### 4. Run the comparison calculations

```bash
python burgers1d/run_burgers.py --case smag --cs 0.20 --restart outputs/1d/reference/state_t0.300000.npz --output outputs/1d/smag_cs020
python burgers1d/run_burgers.py --case coarse --restart outputs/1d/reference/state_t0.300000.npz --output outputs/1d/coarse
```

These use a padded physical grid of 96 while retaining |k|<32.

### 5. Run the zero-target comparison

```bash
python burgers1d/run_burgers.py --case zero-dsm --output outputs/1d/zero_dsm
python burgers1d/run_burgers.py --case zero-reference --output outputs/1d/zero_reference
python burgers1d/run_burgers.py --case zero-raw --output outputs/1d/zero_raw
```

Defaults: cutoff 512, viscosity 0.001, time step 0.0002, and t=0 to 0.8.
The reference uses 3/2 padding; the raw and DSM cases use the unpadded grid.
An unstable raw calculation can terminate with an exception and partial output;
it is not silently stabilized.

### 6. Run the original timing comparison

```bash
python burgers1d/benchmark.py --output outputs/1d/timing.csv
```

Defaults: M=32,48,64,96,128,192,256,384,512; at most 40 timing samples per
method; 0.15 s accumulated timing threshold; two warm-up evaluations; median
time. The four original calculation kernels are preserved. They time one
convection/viscosity update including the relevant zero-target phase selection.
The benchmark has its original branch-selection rule, which is independent
of the previous-step continuity rule in the simulation driver.

Run the timing script without other computations competing for the CPU.

## Two-dimensional calculations

The following are the existing zero-target MSM and comparison configurations.
They do not introduce two-dimensional nonzero-target LES.

```bash
python ns2d/run_ns.py --method msm --output outputs/2d/msm
python ns2d/run_ns.py --method reference --output outputs/2d/reference
python ns2d/run_ns.py --method raw --output outputs/2d/raw
```

For MPI, prepend the launcher, for example:

```bash
mpiexec -n 4 python ns2d/run_ns.py --method msm --output outputs/2d/msm_mpi4
```

Defaults: domain [0,2*pi]^2, Kmax=128, coefficient grids 256 by 256,
viscosity 7.23e-4, RK222, CFL safety factor 0.2, maximum time step 1e-4,
and t=0 to 10. The original deterministic streamfunction phase seed is
20260527 and the initial mean kinetic energy is 1.

MSM uses eight shift samples and the original diagonal condition alpha_x=alpha_y.
The velocity is shifted before each full solver step and shifted back afterward.
The reference uses 3/2 padding; the raw calculation uses neither padding nor MSM.

The original snapshot cadence is retained: every 1000 iterations plus the initial
state. To save more frequently, specify `--snapshot-every`, for example 100.
HDF5 snapshots and the run configuration are written under the selected output
directory only when a calculation is run.

## Options and output conventions

```bash
python burgers1d/run_burgers.py --help
python burgers1d/benchmark.py --help
python ns2d/run_ns.py --help
```

One-dimensional histories use K=<u^2/2>. Positive epsilon means energy removal.
`epsilon_applied` is an instantaneous power diagnostic, not a finite-step energy
difference. Smagorinsky power is evaluated at the saved state, before its split
update. DSM retains the shifted coordinate frame, as in the original calculation.
Saved Fourier states can therefore differ by a translation between methods.

Runtime output filenames are described here so the code can be executed without
additional instructions. No output files are distributed in the source archive.
